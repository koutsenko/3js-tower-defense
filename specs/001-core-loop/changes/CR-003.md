## 1. Причина изменения

Feature-level review подтвердил прохождение текущего automated gate, но выявил
три расхождения реализации с уже утверждёнными требованиями и technical design:

1. момент попадания projectile хранится вне `GameState` и вычисляется формулой,
   не соответствующей фактическому homing movement на маршруте с поворотами;
2. `Restart` заменяет `GameState`, но не сбрасывает fixed-step accumulator;
3. presentation-only transient effects предыдущей session могут оставаться
   видимыми несколько render frames после `Restart`.

Изменение должно привести реализацию к существующим `FR` и `AC`, не меняя
player-visible правила, balance parameters, system order или утверждённые
исходы acceptance scenarios.

## 2. Обнаруженные проблемы

### 2.1 Projectile collision не соответствует фактическому движению

`scheduleProjectileImpact` один раз вычисляет время попадания как:

```text
currentTime + distance / (PROJECTILE_SPEED - MONSTER_SPEED)
```

Эта формула предполагает, что target движется прямо от projectile вдоль линии
сближения. Фактический monster следует маршруту с поворотами, а projectile в
каждом положительном sub-interval направляется к текущей позиции target.

Одновременно `moveProjectiles` при достаточном travel distance устанавливает
позицию projectile в позицию target, но `resolveProjectileHits` разрешает hit
только по отдельно сохранённому времени. Поэтому projectile может визуально и
авторитетно достичь target раньше scheduled boundary либо нанести damage в
момент, не соответствующий фактической траектории.

Время попадания хранится в module-level `WeakMap`, а не в `GameState` и не в
эфемерном prediction, пересчитываемом после каждой boundary. Это создаёт второй
источник mutable gameplay state и нарушает утверждённое правило, что
authoritative gameplay data находятся в сериализуемом `GameState`.

### 2.2 Fixed-step accumulator переживает Restart

`Restart` сбрасывает `GameRuntime`, events и entity ID sequence. Fixed-step
accumulator принадлежит `FixedStepLoop`, не получает уведомления об успешном
`Restart` и сохраняет дробный остаток browser frame time предыдущей session.

В результате новая session может получить первый simulation step после
меньшего, чем полный `1/60 s`, интервала нового browser time. Это не изменяет
initial snapshot, но нарушает утверждённую семантику полного reset.

### 2.3 Transient effects переживают Restart

`TransientEffects` удаляет shot trails и hit flashes по счётчику render frames.
Успешный `Restart` не создаёт presentation event и не очищает этот collection.
Entity reconciliation удаляет towers, monsters и projectiles нового snapshot,
но не затрагивает transient effects. Поэтому визуальные следы завершённой
session могут кратковременно отображаться уже в новом состоянии `Ready`.

## 3. Затронутые требования и решения

### 3.1 Functional requirements и acceptance criteria

- `FR-008`, `AC-006`: projectile должен следовать за живым target и наносить
  damage при фактическом достижении target.
- `FR-013`, `AC-010`, `AC-011`: после terminal transition gameplay должен быть
  заморожен; исправление collision не должно менять утверждённый порядок
  `escape → Defeat → shot → hit → Victory` на одной boundary.
- `FR-015`, `AC-012`: `Restart` должен полностью начинать новую session в
  исходном состоянии без унаследованного timing или visual состояния.

### 3.2 Technical design

Изменение поддерживает уже утверждённые решения `plan.md`:

- §2.1: `GameRuntime` является единственным владельцем mutable gameplay state;
- §5.1: `GameState` содержит сериализуемые authoritative gameplay data;
- §6.2: interval хронологически разбивается по collision boundaries;
- §6.3: projectile движется к текущей позиции target и наносит damage, когда
  фактически достигает его;
- §6.4: `Restart` очищает accumulator, events и presentation-only
  notifications.

## 4. Предлагаемое решение

### 4.1 Projectile collision

- удалить module-level `projectileImpactTimes` и не хранить authoritative
  gameplay timing вне `GameState`;
- прогнозировать ближайшую collision boundary только из current projectile
  position, current target position, текущего участка маршрута и config;
- считать prediction эфемерным: после любой более ранней spawn, escape,
  targeting, projectile-step или terminal boundary отбрасывать его и вычислять
  заново;
- на достигнутой collision boundary фактически проверять, что projectile достиг
  живого назначенного target, и только после этого разрешать hit;
- сохранить fixed `PROJECTILE_SPEED = 8`, homing behavior, отсутствие
  retargeting и приоритет escape над hit;
- не добавлять cached `impactAt` в `ProjectileState`: сохранённое время снова
  стало бы вторым представлением изменяющейся homing trajectory.

Допустимо сохранить внутренний projectile step `1/60 s`, если collision внутри
каждого такого step разрешается на точной boundary и результат остаётся
partition invariant для любого допустимого внешнего `advance(deltaSeconds)`.

### 4.2 Reset fixed-step accumulator

- предоставить application-owned способ сбросить `FixedStepLoop` accumulator;
- выполнять reset только после успешной команды `Restart`;
- не связывать gameplay runtime с browser clock и не переносить accumulator в
  `GameState`;
- после reset первый gameplay step новой session должен требовать полный новый
  `FIXED_STEP_SECONDS` browser-time contribution.

### 4.3 Reset transient presentation state

- добавить явную очистку активных transient effects без disposal всего scene;
- application composition root должен инициировать очистку при успешном
  `Restart` либо при наблюдаемом переходе terminal status в `Ready`;
- очистка не должна создавать gameplay events или authoritative fields;
- обычное frame-based истечение effects внутри одной session сохранить.

## 6. Verification strategy

### 6.1 Gameplay tests

- projectile не наносит damage до фактического достижения target;
- projectile разрешает hit на первой фактической collision boundary;
- target может пересечь поворот маршрута во время полёта;
- одинаковая command sequence и gameplay duration дают эквивалентные snapshot
  и events при coarse, fixed и нерегулярных partitions;
- escape на общей boundary по-прежнему предшествует hit;
- kill, reward и sibling-projectile cancellation остаются атомарными;
- two-tower balance fixture сохраняет `Victory` либо изменение balance
  выносится на отдельное product/design решение.

### 6.2 Application и presentation tests

- fractional accumulator предыдущей session не участвует в новой session;
- неуспешный ранний `Restart` ничего не сбрасывает;
- успешный terminal `Restart` очищает transient effects до первого render
  состояния `Ready`;
- entity reconciliation после Restart остаётся корректным при повторном
  использовании session-local entity IDs.

### 6.3 Verification gate

- `npm test`;
- `npm run lint`;
- `npm run build`;
- manual browser verification полного flow
  `terminal → Restart → Ready → Start → Preparation`, включая отсутствие
  остаточных effects и корректное начало countdown.

Поскольку изменение затрагивает visual timing projectile и Restart, предыдущие
acceptance screenshots сами по себе недостаточны; после implementation нужна
повторная manual browser verification. Обновлять сохранённые screenshots нужно
только если их доказательство визуально изменилось.

## 7. Риски и non-goals

### Риски

- новый collision prediction может создать boundary без временного прогресса и
  бесконечный цикл, если due collision не разрешается фактическим predicate;
- изменение hit timing может выявить зависимость two-tower balance fixture от
  ошибочной старой формулы;
- reset coordination может ошибочно примениться к отклонённому `Restart`.

Для снижения рисков prediction должен гарантировать boundary не раньше current
time, resolver — либо применить due transition, либо позволить последующему
шагу продвинуть время, а reset должен зависеть от успешного `CommandResult`.

### Non-goals

- изменение `PROJECTILE_SPEED`, damage, cooldown, range или wave balance;
- изменение маршрута, tower placement или two-tower fixture;
- добавление pause, сохранения session или восстановления snapshot;
- изменение public `GameRuntime` boundary без отдельного обоснования;
- production animation, новые effects или visual redesign.
