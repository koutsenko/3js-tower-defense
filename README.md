# 3js Tower Defense

Минимальный walking skeleton браузерной Tower Defense на TypeScript, Three.js и
Vite.

Проект реализует полный игровой сеанс: запуск игры, строительство башен,
прохождение одной автоматически запускаемой волны, победу или поражение и
перезапуск в исходное состояние. Игровые правила отделены от Three.js и
браузерного представления, поэтому основная симуляция детерминирована и
тестируется без WebGL.

## Текущее состояние

Feature [`001-core-loop`](specs/001-core-loop/spec.md) реализована на ветке
`master`. Все задачи `T-001`–`T-018` и итоговый acceptance gate имеют статус
`Complete`.

Walking skeleton включает:

- один изометрический уровень с фиксированным маршрутом;
- фиксированную камеру, охватывающую уровень целиком;
- один тип башни и один тип монстра;
- 100 стартовых монет и башни стоимостью 50 монет;
- 20-секундную фазу подготовки;
- одну волну из 10 монстров;
- автоматический выбор целей и видимые снаряды;
- здоровье монстров и базы;
- награду за уничтожение монстров;
- строительство во время подготовки и активной волны;
- HUD, обратную связь при размещении и полосы здоровья;
- состояния `Victory`, `Defeat` и полный перезапуск через `Restart`;
- автоматические тесты gameplay, rendering, UI и browser application;
- опциональный Playwright-сценарий для создания acceptance-скриншотов.

Визуальная часть использует функциональные placeholder-объекты из примитивов
Three.js. Это законченный walking skeleton, но не production-ready игра и не
финальная художественная реализация.

## Игровой цикл

```text
Ready
  └─ Start → Preparation
                └─ через 20 секунд → WaveActive
                                         ├─ база выжила → Victory
                                         └─ HP базы достигло 0 → Defeat

Victory или Defeat ── Restart ──→ Ready
```

### Ready

Исходное состояние сессии:

- 100 монет;
- 3 HP базы;
- 10 оставшихся монстров;
- пустой уровень без башен, монстров и снарядов;
- доступная кнопка `Start`;
- строительство недоступно;
- countdown ещё не запущен.

### Preparation

Нажатие `Start` запускает 20-секундную подготовку. В это время можно строить
башни, но монстры ещё не появляются и не движутся.

После запуска игры кнопка `Start` становится недоступной до конца текущей
сессии.

### WaveActive

Волна начинается автоматически после окончания подготовки, без дополнительного
действия игрока.

Первый монстр появляется сразу, остальные — с интервалом 2 секунды. Башни
автоматически выбирают цели и стреляют. Строительство остаётся доступным,
поэтому заработанные за уничтожение монстров монеты можно потратить во время
волны.

### Victory и Defeat

`Victory` наступает после завершения волны, если база сохранила хотя бы 1 HP.

`Defeat` наступает немедленно, когда HP базы достигает нуля.

После завершения сессии gameplay останавливается, а итоговый экран показывает
результат, количество уничтоженных и пропущенных монстров, оставшиеся монеты и
кнопку `Restart`.

### Restart

`Restart` полностью очищает текущую сессию и возвращает игру в исходное
состояние `Ready`.

## Требования к окружению

Для установки, разработки, сборки и тестирования нужны:

- Node.js `^22.22.2`, `^24.15.0` или `>=26.0.0`;
- npm;
- desktop browser;
- мышь;
- viewport не менее `1280×720` для поддерживаемого отображения игры.

Файл [`.nvmrc`](.nvmrc) фиксирует рекомендуемую для проекта версию Node.js:

```text
24.15.0
```

Chromium и Playwright browser binaries не нужны для обычного запуска приложения
или выполнения `npm test`. Они требуются только для опционального создания
acceptance-скриншотов.

## Установка

Установите зависимости:

```bash
npm install
```

## Локальный запуск

Запустите Vite development server с hot reload:

```bash
npm run dev
```

Откройте в desktop browser локальный адрес, который Vite выведет в терминал.

## Production-сборка

Создайте оптимизированную сборку в каталоге `dist/`:

```bash
npm run build
```

Команда сначала проверяет TypeScript через `tsc --noEmit`, а затем выполняет
production build с помощью Vite.

Каталог `dist/` не предназначен для добавления в Git.

## Тестирование

Запустите полный набор автоматических тестов:

```bash
npm test
```

Тесты проверяют:

- конфигурацию уровня и balance values;
- начальное состояние и lifecycle сессии;
- строительство и причины отказа;
- появление и движение монстров;
- targeting, firing, projectiles и damage;
- экономику убийств и потерю HP базы;
- `Victory`, `Defeat` и `Restart`;
- fixed-step application loop;
- Three.js scene reconciliation;
- HUD и mouse placement;
- композицию browser application.

Для проверки lint и форматирования выполните:

```bash
npm run lint
```

## Управление

Игра полностью управляется мышью.

- Нажмите `Start`, чтобы начать фазу подготовки.
- Наведите указатель на клетку уровня:
  - зелёная подсветка означает, что строительство разрешено;
  - красная подсветка и сообщение объясняют причину отказа.
- Нажмите на свободную разрешённую клетку, чтобы построить башню за 50 монет.
- Во время `WaveActive` продолжайте строить на разрешённых клетках, если хватает
  монет.
- Башни выбирают цели и стреляют автоматически.
- После `Victory` или `Defeat` нажмите `Restart`, чтобы начать новую сессию.

В feature нет обязательных клавиатурных команд. Управление камерой также
отсутствует.

## Опциональные acceptance-скриншоты

Создание скриншотов не требуется для установки, локального запуска,
production-сборки или выполнения автоматических тестов. Этот шаг предназначен
для дополнительной ручной проверки визуального и интерактивного поведения.

Перед первым запуском сценария установите Chromium для Playwright:

```bash
npx playwright install chromium
```

Затем выполните:

```bash
npm run capture:acceptance
```

Сценарий:

1. запускает отдельный Vite server на `127.0.0.1:4173`;
2. открывает приложение в Chromium с viewport `1280×720`;
3. воспроизводит основной победный сценарий;
4. проверяет отказ строительства до `Start`;
5. строит две стартовые башни во время подготовки;
6. проверяет начало активной волны;
7. строит дополнительную башню на заработанные монеты;
8. дожидается `Victory` и проверяет `Restart`;
9. отдельно воспроизводит сценарий `Defeat`;
10. сохраняет скриншоты в
    [`specs/001-core-loop/artifacts/acceptance/`](specs/001-core-loop/artifacts/acceptance/).

Команда перезаписывает PNG-файлы с существующими именами. Она не запускает
`npm test`, `npm run lint` или `npm run build`.

Существующие acceptance-скриншоты:

- [исходное состояние Ready](specs/001-core-loop/artifacts/acceptance/ready.png);
- [отказ строительства до Start](specs/001-core-loop/artifacts/acceptance/pre-start-rejection.png);
- [фаза Preparation с двумя башнями](specs/001-core-loop/artifacts/acceptance/preparation.png);
- [активная волна](specs/001-core-loop/artifacts/acceptance/wave-active.png);
- [строительство на заработанные монеты](specs/001-core-loop/artifacts/acceptance/wave-earned-build.png);
- [Victory](specs/001-core-loop/artifacts/acceptance/victory.png);
- [состояние после Restart](specs/001-core-loop/artifacts/acceptance/restarted.png);
- [Defeat](specs/001-core-loop/artifacts/acceptance/defeat.png).

Скриншоты дополняют автоматические тесты и помогают вручную оценить отображение
уровня, HUD, сущностей, снарядов и итоговых экранов. Они не заменяют полный
manual browser acceptance из технического плана.

## Структура проекта

```text
src/
├── app/          Композиция browser application и fixed-step loop
├── config/       Конфигурация уровня и balance constants
├── game/         Детерминированное состояние и системы gameplay
├── rendering/    Three.js scene, camera, entities, health bars и effects
├── ui/           HUD, final overlay, placement и rejection feedback
└── main.ts       Browser entry point

tests/
├── app/          Тесты application composition и fixed-step loop
├── config/       Тесты конфигурации уровня
├── game/         Headless gameplay и balance tests
├── rendering/    Тесты scene и snapshot reconciliation
└── ui/           Тесты HUD и placement

specs/001-core-loop/
├── spec.md       Утверждённые требования и acceptance criteria
├── plan.md       Утверждённый технический дизайн
├── tasks.md      Задачи реализации и verification checklist
├── changes/      Утверждённые изменения specification и design
└── artifacts/    Архитектурный обзор, отчёты, acceptance scripts и screenshots
```

Gameplay rules и balance configuration не зависят от Three.js, DOM APIs или
browser clock. Rendering и UI отображают authoritative snapshot и передают
пользовательские команды в game runtime.

## Ограничения MVP

Текущая реализация намеренно ограничена:

- одним уровнем;
- одним фиксированным маршрутом;
- одним типом башни;
- одним типом монстра;
- одной конечной волной;
- фиксированными balance values;
- фиксированной изометрической камерой;
- mouse-only управлением в desktop browser;
- English-only интерфейсом;
- placeholder geometry вместо финальных моделей, текстур, анимаций и art
  direction;
- отсутствием сохранения между перезагрузками страницы и игровыми сессиями.

## Out of Scope

В `001-core-loop` не входят:

- улучшение башен;
- продажа или удаление построенных башен;
- выбор между несколькими типами башен;
- несколько типов монстров;
- несколько волн или уровней;
- изменение маршрута башнями;
- пауза;
- изменение скорости игры;
- перемещение, вращение или масштабирование камеры;
- звук и музыка;
- сохранение состояния или прогресса;
- мета-прогрессия;
- мобильная и touch-поддержка;
- локализация и выбор языка интерфейса.
